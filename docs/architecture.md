# Архитектура Finance Radar

## Поток решения

1. `MoexIssProvider` получает дневные OHLCV-свечи через официальный MOEX ISS и приводит их к общей схеме `date/ticker`.
2. `features.py` независимо по каждой бумаге рассчитывает импульс, средние, RSI, ATR, волатильность, устойчивость тренда, пробой и изменение торгового оборота.
3. `GrowthModel` оценивает вероятность достижения заданной доходности на горизонте 10 торговых дней. До обучения доступен детерминированный резервный скоринг.
4. `SignalService` штрафует волатильные сигналы, ранжирует компании и формирует объясняющие факторы.
5. Аллокатор распределяет только часть капитала по профилю риска, ограничивает долю одной бумаги и сохраняет денежный резерв.
6. Бэктест обучается на первых 70% дат и измеряет результат только на следующих 30%, используя защитный временной зазор, неперекрывающиеся окна и транзакционные расходы.
7. FastAPI обслуживает веб-панель, аналитические методы, бумажный счёт и защищённый брокерский адаптер.

## Исполнение

- `PaperBroker` предназначен для симуляции без реальных денег.
- `TInvestClient` по умолчанию работает в sandbox и не отправляет заявку без двух независимых разрешений: переменной `ALLOW_LIVE_TRADING=true` и точной строки подтверждения запроса.
- Токен хранится как `SecretStr`, никогда не возвращается через API и не должен попадать в репозиторий.
- Метод лимита вывода доступен только после локальной настройки счёта. Сам вывод через API брокера недоступен, поэтому выполняется пользователем вручную.

## Границы модели

- Вероятность — оценка модели, а не вероятность гарантированной прибыли.
- Историческая проверка не моделирует все налоги, проскальзывание, дивидендные гэпы и ограничения ликвидности.
- `estimated_units` — число акций, а не лотов. Перед заявкой размер лота нужно получить у брокера.
- Для промышленной эксплуатации нужны база решений, мониторинг качества данных, версионирование модели, аудит заявок и длительная проверка в реальном времени без денег.
